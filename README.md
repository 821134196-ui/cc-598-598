# 汽车玻璃保险直赔与安装验收系统

玻璃门店从**接车报价 → 保险理赔 → 库存确认 → 施工 → 固化/验收 → 交车**全程在同一张工单中办理；
车主通过专属链接实时查看**玻璃型号、保险承担金额、自付金额、预计提车时间**，并对每版报价方案进行确认授权。

- 后端：Python + FastAPI + SQLAlchemy（SQLite）
- 前端：Vue 3（本地化的全局构建，无需 Node 打包）
- 保险回执：模拟保险公司接口（挂载在 `/mock-insurance`，支持延迟与拒赔）
- 图片：保存在本地 `uploads/` 目录

## 一条命令启动

```bash
./start.sh
```

启动后访问：

| 入口 | 地址 |
|---|---|
| 门店系统（工单列表/详情/施工/交车） | http://localhost:8000 |
| 车主页 | 工单详情页右上角「车主页 ↗」（每单独立令牌链接） |
| 业务 API 文档 | http://localhost:8000/docs |
| 模拟保险接口文档 | http://localhost:8000/mock-insurance/docs |

首次启动自动建库、初始化玻璃库存，并生成一条演示工单（沪A·D12345）。

## 运行测试

```bash
.venv/bin/python -m pytest tests/ -v
```

7 个用例覆盖全部关键规则：完整流程、固化未到禁交付、验收未过禁交付、
拒赔改价需重新授权、迟到回执不改错工单、暂停恢复需新方案、开工前置门槛。

## 核心业务流程

```
接车建单(初始报价v1) → 车主确认 → 提交保险理赔 → 回执批复 ─┐
                          │              └ 拒赔 → 生成自费新报价v2 → 车主重新授权
                          ├ 车主变更方案 → 新报价 → 车主确认（迟到的回执将被忽略）
                          ↓
                    确认库存(预留玻璃) → 开始施工 → 上传照片 → 登记固化截止时间
                          │              └ 型号不符/新破损 → 暂停 → 新方案+车主确认 → 恢复
                          ↓
                    登记验收结果 → 交付检查全部通过 → 交车
```

## 关键规则（服务端强制）

1. **交付门槛**：以下全部满足才允许交车，`POST /api/workorders/{id}/deliver` 服务端复核，
   前端按钮禁用仅为提示：
   - 当前报价已获车主确认授权（**最新一版报价待确认时一律禁止交付**——拒赔改价必须重新授权）
   - 费用方案已确定（保险已批复或自费已确认）
   - 施工未暂停、已上传安装照片、已登记安装完成
   - **固化截止时间已到**、**安装验收通过**
2. **拒赔转自费**：理赔拒赔后生成新报价（自费），车主确认后生效；**原报价保留**为历史版本（SUPERSEDED），
   报价版本表完整可查。
3. **迟到回执不覆盖已确认方案**：理赔单绑定提交时的报价版本；回执应用时若当前已确认版本
   与之不同（车主已变更方案），回执标记 `STALE`，只写事件日志，**不修改任何金额与方案**。
4. **施工暂停**：发现型号不符/新破损 → 暂停；必须生成新方案报价（强制填写方案说明）并经车主确认
   才能恢复；玻璃型号变更会自动释放原库存预留，需重新确认库存。
5. **开工门槛**：报价已确认 + 库存已按当前报价型号预留 + 保险方案已批复（自费方案除外）。

## 演示脚本

### 场景一：拒赔改价需重新授权
1. 新建工单（保险直赔），车主页确认报价 → 「报价与保险」提交理赔，模拟结果选「拒赔」→「刷新回执」
2. 状态变为「保险拒赔·待新方案」，此时无法开工、交车检查不通过
3. 「生成新报价」选「拒赔转自费」→ 车主页确认授权 → 继续施工交车；报价表中原报价保留

### 场景二：未固化不能提前交付
施工页登记固化截止时间（设为未来），交车页红色横幅「当前不允许交付」，固化项 ✗；
时间过后刷新变为 ✓ 方可交车。

### 场景三：迟到回执不改错工单
1. 提交理赔时把「回执延迟」设为 60 秒
2. 回执到达前：生成「车主变更方案」自费报价并让车主确认
3. 60 秒后「刷新回执」→ 理赔标记「迟到回执·未应用」，事件日志记录忽略原因，金额保持自费方案不变

## 目录结构

```
backend/
  main.py            FastAPI 应用与全部业务 API
  services.py        业务规则：交付门槛、回执应用、报价确认、状态推导
  models.py          SQLAlchemy 模型（工单/报价版本/理赔/施工/照片/库存/事件）
  mock_insurance.py  模拟保险公司接口（独立子应用，回执可延迟）
  seed.py            库存与演示工单初始化
frontend/
  index.html app.js styles.css   Vue 3 单页应用（无打包步骤）
  vendor/vue.global.prod.js      本地化的 Vue，离线可运行
tests/test_rules.py  业务规则测试
start.sh             一条命令启动
uploads/             安装照片（本地存储）
```

## 说明

- 模拟保险接口与业务后端同进程但为独立子应用，业务侧通过 HTTP（ASGI 传输）调用，
  与对接真实外部保险接口的调用方式一致；回执默认规则：申请金额 > 8000 元拒赔，
  提交时可指定延迟秒数与强制结果便于演示。
- 批复金额与报价不一致时，系统自动把该版报价退回「待车主确认」，需重新授权后方可继续。
